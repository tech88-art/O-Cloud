## Why a custom DRA driver

Per `docs/adr/0001-phase0-key-decisions.md` §5 v3 (双轨路径) and §7:

- **Edge path (KubeEdge)** stays on Ascend Device Plugin v1 — KubeEdge v1.22
  has no DRA support, so the edge cluster cannot consume DRA today.
- **Standard-K8s small-cluster path** is the DRA spike target — this driver
  publishes `resource.k8s.io/v1beta1` ResourceSlices that map directly to
  the four-level NPUSlicePool CRDs.
- Self-research over MindCluster: MindCluster is black-box and cannot
  express our Ocloud-specific dynamic slicing.

Fork-spirit: `kubernetes-sigs/dra-example-driver` v0.2.1.

## Getting started

```bash
cd operators/npu-dra-driver

# Phase 4 scaffold-time loop:
make build        # produces bin/manager (alias: make manager)
make run          # runs manager on host kubeconfig (no controllers registered)

# Phase 4 ENVTEST harness (T003 ships a skeleton; T005/T006 fill in tests):
make test

# Phase 4 T101 (W2): real docker build / helm chart deploy
make docker-build IMG=npu-dra-driver:v0.1.0
```

## Phase 4 simulator scope

**This driver does NOT touch real Ascend NPUs in Phase 4.** It runs against
the synthetic NPU set in `configs/mock-data/set-a-small/npus.json` (2 nodes ×
8 NPUs). CI runs in a kind cluster on `ubuntu-latest`. Real hardware
verification is deferred to Phase 7 — see `docs/cann-driver-matrix.md` §4 for
the Phase 7 entry checklist.
